# Linux DO 大模型排行榜 —— 技术方案

> 版本：v0.5
> 状态：新增公告功能；管理后台 v1 提前到第一阶段；MVP 路线重排

---

## 一、项目定位

面向 Linux DO 社区的、由用户投票产生的大模型排行榜站点。**只做榜单，不做试炼场**。

核心价值：
- 一处看清各家模型在不同维度上的真实口碑
- 评价由社区真人给出，而非厂商自卖自夸
- 讨论沉淀在本站，形成独立的社区氛围

## 三、核心概念

### 3.1 三层分类结构

```
大类（开源属性）
  └─ 分类（模态）
       └─ 模型
            └─ 多维度评分
```

- **大类**：开源 / 非开源（两个）
- **分类**：文字模型 / 生图模型 / 生视频模型（可扩展）
- **模型**：具体一个模型条目，归属某大类下的某分类
- **维度**：每个分类有自己的一组评分维度

### 3.2 各分类的维度（初版）

| 分类 | 维度 |
|------|------|
| 文字模型 | 代码能力、RP 能力、任务执行、推理能力、长文本、中文表达 |
| 生图模型 | 写实度、艺术性、Prompt 遵循、出图速度 |
| 生视频模型 | 画面连贯性、画质、Prompt 遵循、时长能力 |

> 维度由后台可配置，不写死在代码里。

### 3.3 模型生命周期

```
[草稿] → [观察区] → [正式榜] → [归档]
```

| 状态 | 说明 | 进入条件 |
|------|------|----------|
| 草稿 | 仅管理员可见 | 后台新建 |
| 观察区 | 站点显示「新」标签并置顶；可投票，但不计入排行 | 管理员发布 |
| 正式榜 | 计入排行，参与排序 | 发布时间 ≥ 7 天 **或** 总票数 ≥ 50 |
| 归档 | 仅在历史页面可见 | 管理员手动归档 |

## 四、评分与排序机制

### 4.1 评分规则

- **范围**：1–10 整数
- **弃权 / 不熟**：用户不操作该维度即可；数据库里不会写入该维度的评分记录，自然不计入均分
- **撤回**：已评过的维度可点"撤回"，删除该评分记录并追加一条 `vote_history` 审计记录
- **粒度**：用户可针对每个维度独立打分；允许只评一部分维度
- **修改**：允许修改，每次修改记录历史
- **频次**：每个用户对每个模型每个维度只能有一条当前有效评分

### 4.2 准入门槛（防刷）

依赖 Linux DO OAuth 返回的 `trust_level`：

| 等级 | 浏览 | 评论 | 投票 |
|------|------|------|------|
| 0（新用户） | ✅ | ✅ | ❌ |
| 1+ | ✅ | ✅ | ✅ |

> 此门槛可在后台调整。

### 4.3 排序算法：贝叶斯平均

直接用算术平均会让"3 个人投全 10 分"的模型霸榜。改用贝叶斯平均做排序：

```
weighted_score = (C × m + n × avg) / (C + n)

n   = 该维度的有效投票数
avg = 该维度的算术均分
m   = 该分类下、该维度的全站均分
C   = 平滑系数，初始设为 30
```

- **页面展示**：真实均分（用户感知直观）
- **背后排序**：贝叶斯均分（公平）
- 排行表格里同时显示"票数"列，让用户自己判断可信度

### 4.4 综合分

```
综合分 = 各维度贝叶斯均分的平均（默认等权）
```

**进阶（第二阶段）**：用户可在前端拖滑块自定义权重（例如"代码能力 ×2、RP ×0.5"），表格实时按个人偏好重排。该功能完全在前端计算，不写回数据库。

### 5.3 移动端

表格变卡片列表：

```
┌────────────────────────────┐
│ GPT-5          综合 8.7 ★  │
│ ──────────────────────     │
│ 代码  ████████░░  9.2      │
│ RP    ███████░░░  7.8      │
│ 任务  ████████░░  8.9      │
│ 1234 票           [详情]   │
└────────────────────────────┘
```

顶部固定一个"排序方式"下拉选择按哪个维度排。

### 5.4 模型详情页

- 模型基本信息（logo、官网、所属机构、参数量、上下文长度等元数据）
- 各维度评分柱状图 + 票数 + 评分分布直方图
- 评分趋势曲线（按周聚合）
- 用户对该模型的评价摘要
- 站内评论区（见 5.5）
- 我的评分（已登录时显示，可修改）

### 5.5 评论 / 留言

每个模型详情页底部带评论区。规则：

**准入：**
- 浏览评论：不限
- 发表评论：登录 + `trust_level >= 1`（与投票门槛一致）

**功能：**
- 一级评论 + 二级回复（最多两层，避免过深嵌套）
- 支持 Markdown（受限子集：粗体、斜体、行内代码、代码块、链接、引用），不允许 HTML
- 点赞 / 点踩
- 排序：默认"按热度"（点赞数 - 时间衰减），可切换"最新"
- 删除：作者本人 / 管理员
- 编辑：作者本人 15 分钟内可编辑，编辑后显示"已编辑"标记

**反垃圾与审核：**
- 频率限制：单用户每分钟 ≤ 3 条评论
- 关键字过滤（黑名单可在后台维护）
- 用户举报按钮，被举报次数达阈值自动隐藏并进入审核队列
- 后台审核面板：放行 / 删除 / 封禁作者
- 自动隐藏规则：被点踩数 - 点赞数 ≥ N 时折叠（用户可点击展开）

> 评论功能涉及反垃圾、审核工作量较大，**建议放在第二阶段开发**：第一阶段先把核心榜单跑稳定，第二阶段再补站内评论。如要在第一阶段同时上线，开发周期需要再加 1–2 周。

### 5.6 公告

管理员向全站用户发布通知（新模型上线、规则变更、社区活动等）。

**展示位置：**
- 排行榜页顶部、引导条上方：**置顶且 active 的最新一条**横条显示（带"× 关闭"按钮，关闭后 24 小时内不再出现，浏览器 cookie 存状态）
- `/announcements` 页：完整列表，最新在上，含历史
- `/announcements/[id]`：单条详情（评论区可选，第二阶段再开）

**内容：**
- 标题 + 正文（Markdown，受限子集与评论一致：粗体/斜体/行内码/代码块/链接/引用）
- 不允许 HTML，渲染时 sanitize
- 长度限制：标题 ≤ 80 字，正文 ≤ 5000 字

**权限与生命周期：**
- 创建 / 编辑 / 下线 / 删除：仅管理员
- `is_active = false`：草稿或下线状态，不在前台显示
- `is_pinned = true`：在 `/announcements` 列表中置顶
- 横条只展示 **active + pinned + published_at 最新**的那一条

### 5.7 管理后台 `/admin`

**第一阶段最小集**（第八节细述）：

- 仪表盘（/admin）：当前用户数 / 模型数 / 评分数 / 最新一条公告等数字
- 公告管理（/admin/announcements）：CRUD + 上下线 + 置顶
- 模型管理（/admin/models）：CRUD + 状态切换（草稿 → 观察区 → 正式榜 → 归档）+ 关联 license/category
- 维度管理（/admin/dimensions）：按分类增删改维度

**第二阶段**再补：用户管理（封禁）、评论审核、关键字黑名单、评分异常检测、审计日志查询。

## 六、数据库 Schema

```ts
// 用户
users {
  id              uuid PK
  linuxdo_id      bigint UNIQUE         // Linux DO 用户 ID
  username        text
  display_name    text
  avatar_url      text
  trust_level     int                   // 0-4
  is_admin        boolean default false
  is_banned       boolean default false
  created_at      timestamptz
  last_login_at   timestamptz
}

// 大类（开源 / 非开源）
licenses {
  id     int PK
  slug   text UNIQUE                    // open-source | closed-source
  name   text                           // 开源 | 非开源
  order  int
}

// 分类（文字 / 生图 / 生视频）
categories {
  id     int PK
  slug   text UNIQUE                    // text | image | video
  name   text                           // 文字模型 | 生图模型 | 生视频模型
  order  int
}

// 维度（按分类配置）
dimensions {
  id           int PK
  category_id  int FK -> categories
  slug         text                     // code | rp | task | ...
  name         text                     // 代码能力 | RP 能力 | ...
  description  text
  order        int
  UNIQUE(category_id, slug)
}

// 模型
models {
  id              uuid PK
  license_id      int FK -> licenses
  category_id     int FK -> categories
  name            text                  // GPT-5
  slug            text UNIQUE           // gpt-5
  vendor          text                  // OpenAI
  logo_url        text
  homepage_url    text
  description     text
  context_length  int                   // 文字模型用
  params          text                  // 参数量描述，如 "70B"
  released_at     date
  status          text                  // draft | observing | listed | archived
  pinned          boolean default false // 是否在观察区置顶
  published_at    timestamptz           // 进入观察区的时间
  created_at      timestamptz
  updated_at      timestamptz
}

// 评分（每用户对每模型每维度一条当前记录）
votes {
  id           uuid PK
  user_id      uuid FK -> users
  model_id     uuid FK -> models
  dimension_id int FK -> dimensions
  score        int                      // 1-10（0 分代表撤回，单独表示）
  created_at   timestamptz
  updated_at   timestamptz
  UNIQUE(user_id, model_id, dimension_id)
}

// 评分历史（每次修改追加一条，便于审计 / 反刷）
vote_history {
  id           uuid PK
  vote_id      uuid FK -> votes
  user_id      uuid
  model_id     uuid
  dimension_id int
  score        int
  action       text                     // create | update | withdraw
  created_at   timestamptz
  ip_hash      text                     // 仅存哈希，用于反刷
  user_agent   text
}

// 模型评分聚合缓存（每小时定时刷新或写入时增量更新）
model_stats {
  model_id      uuid
  dimension_id  int
  vote_count    int                     // 有效票数（不含 0）
  avg_score     numeric(4,2)            // 真实均分
  weighted_score numeric(4,2)           // 贝叶斯均分
  updated_at    timestamptz
  PRIMARY KEY(model_id, dimension_id)
}

// 操作日志（后台用）
audit_logs {
  id          uuid PK
  actor_id    uuid FK -> users
  action      text                      // model.create | model.update | user.ban | ...
  target_type text
  target_id   text
  payload     jsonb
  created_at  timestamptz
}

// 评论
comments {
  id              uuid PK
  model_id        uuid FK -> models
  user_id         uuid FK -> users
  parent_id       uuid FK -> comments NULL  // 二级回复时指向父评论
  content         text                       // Markdown 原文
  content_html    text                       // 渲染并清洗后的 HTML（缓存）
  like_count      int default 0
  dislike_count   int default 0
  report_count    int default 0
  is_hidden       boolean default false      // 被举报或人工隐藏
  is_deleted      boolean default false      // 软删除
  edited_at       timestamptz NULL
  created_at      timestamptz
  ip_hash         text
  INDEX(model_id, created_at)
  INDEX(user_id)
}

// 评论点赞 / 点踩
comment_reactions {
  id          uuid PK
  comment_id  uuid FK -> comments
  user_id     uuid FK -> users
  reaction    text                           // like | dislike
  created_at  timestamptz
  UNIQUE(comment_id, user_id)
}

// 评论举报
comment_reports {
  id          uuid PK
  comment_id  uuid FK -> comments
  reporter_id uuid FK -> users
  reason      text                           // spam | abuse | off_topic | other
  detail      text
  status      text                           // pending | resolved | rejected
  handled_by  uuid FK -> users NULL
  handled_at  timestamptz NULL
  created_at  timestamptz
  UNIQUE(comment_id, reporter_id)
}

// 关键字黑名单（后台可维护）
banned_keywords {
  id          int PK
  pattern     text                           // 普通字符串 / 正则
  is_regex    boolean default false
  action      text                           // block（拒绝发布） | hide（自动隐藏）
  created_by  uuid FK -> users
  created_at  timestamptz
}

// 公告
announcements {
  id            uuid PK
  title         text NOT NULL                 // ≤ 80 字
  content       text NOT NULL                 // Markdown 原文
  content_html  text NOT NULL                 // 渲染并 sanitize 后的 HTML
  is_active     boolean default false          // false = 草稿 / 下线
  is_pinned     boolean default false          // 是否置顶
  published_at  timestamptz                    // 进入展示的时间
  created_by    uuid FK -> users
  created_at    timestamptz
  updated_at    timestamptz
  INDEX(is_active, published_at)
}
```

## 七、API 设计

约定：JSON 接口，认证用 Auth.js session cookie。

### 7.1 公开接口

```
GET  /api/rankings?license=open-source&category=text
       → 返回当前榜单的所有正式模型 + 各维度统计

       → 观察区模型（带「新」标签）

GET  /api/models/:slug
       → 模型详情 + 各维度评分 + 趋势数据

GET  /api/models/:slug/stats?range=30d
       → 趋势数据

       → 模型评论列表（默认按热度，可选 latest）

GET  /api/announcements?active=true
       → 公告列表（默认仅 active）
GET  /api/announcements/active-banner

       → 单条公告
```

```

       body: { modelId, parentId?, content }
       → 发表评论 / 回复（trust_level >= 1）

POST   /api/comments/:id/reaction

POST   /api/comments/:id/report
       body: { reason, detail? }
       → 举报
```

## 八、Linux DO OAuth 接入

Linux DO 的 OAuth2 端点（`connect.linux.do`）：

```
授权:    GET  https://connect.linux.do/oauth2/authorize
换 token: POST https://connect.linux.do/oauth2/token
用户信息: GET  https://connect.linux.do/api/user
```

返回字段中包含 `trust_level`，作为投票门槛依据。

接入方式：在 Auth.js 中实现一个自定义 `OAuthProvider`：

```ts
// auth.config.ts 伪代码
const LinuxDoProvider = {
  id: "linuxdo",
  name: "Linux DO",
  type: "oauth",
  authorization: "https://connect.linux.do/oauth2/authorize",
  token:        "https://connect.linux.do/oauth2/token",
  userinfo:     "https://connect.linux.do/api/user",
  clientId:     process.env.LINUXDO_CLIENT_ID,
  clientSecret: process.env.LINUXDO_CLIENT_SECRET,
  profile(p) {
    return {
      id: p.id,
      name: p.username,
      image: p.avatar_url,
      trust_level: p.trust_level,
    };
  },
};
```

每次登录时把 `trust_level` 同步进 `users` 表。

## 十、防刷策略

最低限度：

1. **登录门槛**：必须 Linux DO 登录，且 `trust_level >= 1` 才能投票
2. **唯一性约束**：数据库层 `UNIQUE(user_id, model_id, dimension_id)` 防止同一用户对同维度重复投
3. **审计字段**：`vote_history` 记录 IP 哈希、UA、时间戳
4. **频次限制**：单用户每分钟最多 N 次投票请求（中间件层）
5. **观察期保护**：观察区不计入排名，新模型刷高分也不会立即上榜
6. **管理员复核**：后台异常面板 + 一键撤销某用户全部投票

进阶（暂不做，按需启用）：

- 引入 `trust_level` 加权（高级别用户的票分量更大）
- 接入 Cloudflare Turnstile 抵御自动化脚本

## 十一、性能与缓存

- **榜单读取热**：`/api/rankings` 可能每秒被大量请求 → **结果缓存到 KV，TTL 60s**
- **聚合统计**：`model_stats` 表通过定时任务（Vercel Cron）每 5 分钟全量重算一次；写投票时同步增量更新（双保险）
- **首屏渲染**：榜单页用 Next.js ISR（Incremental Static Regeneration），revalidate 60s
